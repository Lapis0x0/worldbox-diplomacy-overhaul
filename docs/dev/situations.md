# 局势

局势把原本藏在代码里的政治事件摆到台面上。议会负责固定议题的定期表决，局势处理表决解决不了的权力斗争，不提议案，也不改政策。

## 定义

每种局势是一个 `SituationDef`，继承[议题](parliament.md#表决) `Issue`，固定两档：左头结局在 −½，右头结局在 +½。

| 字段 | 含义 |
|---|---|
| `axis`、`load`、`lean` | 议题的政治轴、载荷和各家的处境，载荷取负数时翻转方向 |
| `years` | 基准时长：合力为 1 时走完全程的年数 |
| `start` | 开局时的进度，默认 20 |
| `favor` | 对发起方的好感在态度里的权重，默认 0.5 |
| `trigger` | 每年判定是否开局；由事件开局的局势留空，直接调用 `Situations.Open` |
| `initiator` | 开局时定下发起的势力，之后不变 |
| `onLeft`、`onRight` | 走到左头、右头时执行 |
| `moot` | 局势的前提已经不在：直接结束，不执行结局，也不记恩怨 |
| `pressures` | 大势：议会之外的因素，单位和推力相同，往右头推为正，可以随局势年数变化 |
| `stages` | 三个阶段各自的候选 |
| `pushes` | 各阶段抽中的候选带来的推力，默认 0.05、0.10、0.15 |

## 推进

进度从 0 到 100，每年在国家的结算月推进一次：

```
政见得失 = 左头离理想位置的距离 − 右头离理想位置的距离
态度 = 政见得失 + 好感权重 × 对发起方的好感 ÷ 100 − 惯性 0.1，限制在 ±1
推力 = 议席占比 × 态度
进度每年变化 = (各方推力之和 + 大势 + 抽中的候选) × 100 ÷ 基准时长
```

- 集团沿用议会的合并规则：成员取集团按议席加权的平均分。
- 发起方和它所在的集团态度固定为 1。
- 进度走到 0 是左头结局，走到 100 是右头结局。
- 发起的势力灭亡或失去全部议席时，局势走到左头，`onLeft` 收到的势力是空。
- `moot` 成立时局势直接结束，每年在推进之前判定。
- 议会关闭时不开新局势，进行中的局势直接结束，不执行结局。

## 阶段

进度 0–33、33–67、67–100 分成三个阶段。每个阶段有若干候选，每个候选有名字、城市忠诚或军队伤害的修正，以及它是不是转机。

- 进入阶段时随机抽一个候选，只有抽中的生效，之前阶段抽中的效果继续保留。
- 退回上一阶段时摘掉刚退出那个阶段的效果，再次进入时重新抽。
- 抽中的坏事往右头推，转机往左头拉，力度由 `pushes` 决定。
- 一个国家有多场局势时，效果相加。
- 城市归心不计算局势带来的忠诚修正，避免衰落自我加速。

## 落幕

- 走到右头：反对的势力按态度记恨发起方，支持的势力对发起方记下恩情。
- 走到左头：发起方按态度记恨反对它的势力。

## 将领夺权

崩溃期每年掷 10%（「勇者晋升」20%），掷中后开局，见[乱世夺权](government.md#乱世夺权)。

| 定义 | 内容 |
|---|---|
| 发起方 | 杀敌最多的队长或士兵所在的家族，要有议席、不是王室或宗室（共和国是执政家族），他也会起事（已经是军事共和国时要有野心） |
| 议题 | 分权 ↔ 集权，载荷 1。处境：拿主意的人尚武 +0.3，离首都的远近 × −0.3，王室和宗室 −1 |
| 大势 | 禁军欠饷 +0.15；不在崩溃期时朝局回稳 −0.3 |
| 基准时长、开局进度 | 10 年，20 |
| 左头 | 发起家族杀敌最多的将领解甲（`stopBeingWarrior`），世界日志记一条 |
| 右头 | 发起家族眼下杀敌最多的将领夺权，没有将领时由拿主意的人出面，按[乱世夺权](government.md#乱世夺权)的性格规则；没有野心、国家已经是军事共和国时改由他执政 |
| `moot` | 发起家族成了王室、宗室或执政家族，或者关掉了历史事件改制 |

| 阶段 | 坏事 | 坏事 | 转机 |
|---|---|---|---|
| 拥兵 | 兵为将有：军队伤害 +5% | 骄兵悍将：城市忠诚 −10 | 朝廷犒军：城市忠诚 +10 |
| 跋扈 | 功高震主：城市忠诚 −20 | 军纪败坏：军队伤害 −5% | 诏令犹行：城市忠诚 +10 |
| 逼宫 | 禁军逼宫：城市忠诚 −40 | 甲士入城：军队伤害 +8% | 忠臣护驾：城市忠诚 +15 |

## 界面

- 图标 `ui/Icons/vd_situation`：红蓝两人背对背，中间一道闪电，草图和生成脚本在 `.art/situation/`。局势的世界日志都用它。
- 选中王国时，右下角议会按钮的上方是局势按钮，和议会按钮一样一直显示。悬停列出进行中的局势和当前阶段，阶段名按进度条上那一段的颜色；点击打开局势窗口。
- 局势窗口（`SituationWindow.cs`）也从王国窗口左侧页签栏打开，排在选举与任命后面，议会关闭时隐藏。
  - 左边是局势卡片：进行中的在前，落幕 20 年内的调暗排在后面，写「N 年前」。
  - 右边依次是起因、进度条（按阶段从琥珀到红，走过的实色、没走到的压暗）、三个阶段的候选（抽中的点亮并写出效果，其余调暗、悬停看效果）、两头结局。
  - 进行中的再加趋势行（进度、每年变化、约几年进入下一阶段或走到一头）和两边对垒：左右两栏对应两头，栏头是原版绸带写立场，各分大势和各方。王室第一、宗室第二、发起方第三，其余按推力排；同一个集团收成一行，悬停看成员；单股势力悬停看议席、政见得失和对发起方的好感。推力为零的列在底部的观望，王室除外。
  - 局势一年只变一次：打开窗口和数据指纹变了才算推力明细。
- 起因、结局说明用语言 key `<id>_desc`、`<id>_left_desc`、`<id>_right_desc`，`$clan$` 换成发起家族；栏头用 `<id>_side_left`、`<id>_side_right`。

## 实现

| 文件 | 内容 |
|---|---|
| `Issue.cs` | 议题 |
| `SituationDef.cs` | 局势、候选和大势的数据结构 |
| `Situations.cs` | 开局、推力、每年推进、落幕 |
| `Situations.Effects.cs` | 汇总阶段效果 |
| `Situations.History.cs` | 落幕记录 |
| `Defs/*.cs` | 各局势的定义，一个局势一个文件，在 `Situations.Init` 注册 |

语言 key 由局势 id 拼出：局势名 `<id>`，两头 `<id>_left`、`<id>_right`，阶段 `<id>_stage0` 到 `_stage2`；大势和候选的名字用它们自己的 id。

开发命令 `sit` 列出进行中的局势和推力明细，也能开局、拨进度、直接结算、单独推进一个国家，见 `Dev.cs` 顶部。

`kingdom.data` 里的键：

| 键 | 含义 |
|---|---|
| `<局势 id>_progress` | 进度，进行中的局势才有 |
| `<局势 id>_since` | 开局的年份 |
| `<局势 id>_by` | 发起势力的 `ParliamentClan.Key` |
| `<局势 id>_pick0` 到 `_pick2` | 各阶段抽中的候选下标 |
| `<局势 id>_end_year`、`_end_since`、`_end_right`、`_end_by`、`_end_pick0` 到 `_end_pick2` | 最近一次落幕：年份、开局年份、是否走到右头、发起家族的名字、各阶段抽中的候选；20 年后清掉 |
| `vd_sit_loyalty` | 全部局势的城市忠诚修正之和 |
| `vd_sit_damage` | 全部局势的军队伤害百分比之和 |
