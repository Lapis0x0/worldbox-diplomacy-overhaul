## 系统之间的关系

- **王朝周期是中枢。** 周期阶段影响附庸好感、城市忠诚、附庸会不会密谋独立、大国会不会分封城市、弱国会不会称臣，也决定共和国能不能称帝、将领能不能夺权。
- **战争靠谈判结束。** 打到差不多时交战双方和谈，按战果赔款、让出附庸或称臣，见[和谈](peace.md)。
- **附庸是外交的基本单位。** 投降、分封、称臣都产生附庸；附庸和宗主组成一个集团，战争同进同退；周期衰落时附庸离心，大叛乱时附庸纷纷独立。
- **政体跟着国家的经历变。** 新国家按文化掷出政体，之后由王室绝嗣、称帝、夺权和议会改变；成为附庸、获得独立都会改变称号。
- **钱有去处。** 城主上缴的钱进国库，城市用自己仓库的金子养兵，多余的上缴；国王发起密谋、战败赔款都动国库，见[国库与军饷](economy.md)。
- **国策由氏族决定。** 各氏族按占的城分得议席，按立场表决税收、分封、政体、海军、战和、对待附庸和宗主的政策；扩张后地方氏族坐大，能和王室分庭抗礼。

## 代码结构

|---|---|

| `Code/Diplomacy/` | 附庸、阵营、封建、整合度、独立、和谈、联盟地图 |
| `Code/Government/` | 政体、王朝周期、议会与政策、氏族与选官 |
| `Code/Economy/` | 国库与军饷 |
| `Code/Military/` | 军队命令、禁军和国家指挥、攻城、框选下令 |
| `Code/UI/` | 窗口和王国的显示 |
| `Code/Powers/` | 神力和 Tab |
| `Code/Perf/` | 性能优化和开发命令 |

每个系统一个静态类，自己的数据键、补丁、好感和忠诚项都放在自己的文件里，在 `Init` 里注册。按年或按月跑的逻辑加进 `Clock.cs`；一个原版方法被几个系统同时用到时，只在 `Hooks.cs` 挂一个补丁，在里面按顺序调用各系统（`Perf/` 自成一体，不在此列）。

## 时间

模组里的"年"是原版的游戏年（60 个世界时间单位，原版一个月是 5）。

| 频率 | 做什么 |
|---|---|
| 每年 | 政体事件（任期、夺权、称帝）→ 政体称号更新 → 王朝周期推进 → 整合度变动 → 强制同化 → 城市发地方兵军饷、多余的金子上缴国库、国库发禁军军饷 → 到期的国家开议会 |
| 原版的密谋节奏（每位国王约 1–1.5 年一次） | 国王按动机考虑独立、威逼称臣、中兴、分封宗室、收归直辖、和谈密谋 |
| 每场战争每年 | 没人在谈时，双方国王按动机考虑发起和谈 |
| 大约每月 | 把所有附庸的战争状态和宗主同步一次 → 各城禁军人数向兵制名额调整 → 国家给禁军编队派任务 → 地方军安排驻守和出击 |
| 原版的决策节奏 | 立新君主、城市挑进攻目标、军队行动，模组在这些原版流程里插入自己的逻辑 |

## 数据保存

模组的状态都写在原版对象的自定义数据里（`kingdom.data`、`city.data`、`war.data`），随原版存档保存，键名都以 `vd_` 开头。装模组之前的存档可以直接用：缺少的数据在第一次判定时补上。

只有一样东西不进存档：玩家下的**进攻命令**。读档或热重载后，城市回到原版 AI 挑目标。驻扎、扎营是存档的。

## 与其他模组

王国之间的好感逐项计算：某一项（原版的、本模组的或其他模组加的）出错时，这一项按 0 计，其余照常累加。每个出错的项只在日志里记一次，带上项的 id 和两个王国的名字。原版遇到这种情况会让整次计算作废并报错，每次算好感都会刷屏。

原版存档时会按 id 重新找一遍外交关系里的两个王国，找不到就把引用留空，关系本身却还在，之后这两国每次算好感都会报错。取外交关系时如果发现引用为空，就用这次传进来的两个王国补上。

## 异常隔离

原版每帧的更新没有任何异常保护：模拟里城市、单位、建筑、军队、国家、外交、密谋、战争、弹道、状态效果依次更新，之后是玩家操作、名牌和渲染。任何一环抛异常，这一帧排在它后面的全被跳过；抛异常的条件不变，就每帧如此。轻则某个系统停摆，重则画面定住、点什么都没反应（模拟其实还在跑），同时每帧往日志里写一遍堆栈，越来越卡。原版的状态还彼此依赖：弹道没更新，「这个国家还有箭在飞」就登记不上，国家可能被提前移除，又造出新的每帧报错（见下文弹道）。所以一次偶发的异常可能变成永久的卡死。

模组和原版之间分两层防护。

### 模组这一侧：补丁不把异常抛进原版

模组按系统分组（`Safety.cs` 的 `Sys`：附庸、和谈、政体、王朝周期、议会、军事、国库、界面显示）。每个前缀、后缀补丁：

1. 先问 `Safety.On(系统)`，系统停用了就照原版
2. 自己的逻辑包在 `try` 里，出错交给 `Safety.Fail(系统, 位置, 异常)`，然后照原版（前缀返回 `true`）

事件补丁（城市换国家、开战、结束战争……）尤其要这样：模组的逻辑出错，不能把原版的操作打断在一半。

两种例外：
- **替换了原版、又已经改动了游戏状态的补丁**，出错时不再交给原版，否则原版会再做一遍：钱已经从国库扣了（密谋花钱）、税已经分出去了（城主上缴）、船已经造出来了、执政已经选出来了、国家已经改成共和国了。补丁记下自己做到了哪一步，在 `catch` 里据此决定交不交给原版
- **清理**（国家移除时释放它的附庸）不受熔断控制，系统停用了也照做，免得留下指向已移除对象的引用`Clock` 的年度、月度结算按系统归属同样处理。

**熔断**：同一个系统 30 秒内出错 5 次，本局停用这个系统的全部补丁和定期结算，改走原版，屏幕上提示一次「外交大修的「某某」功能出错，本局已暂停」；读档或新建世界后恢复。同一个 bug 通常会反复触发，开开停停反而容易留下做了一半的状态。开发命令 `safety fail <系统> <次数>` 可以模拟。

**审计**：开发时游戏启动后检查模组的每个前缀、后缀补丁，方法体里没有 `try` 的写进 `out.log`（`@unguarded`），最后一行 `@audit` 是总数。不需要兜底的补丁（异常在它调用的地方已经兜住、只读一两个字段）标 `[SafeBy("理由")]`。

### 原版这一侧：每一环各自兜底

原版和模组漏掉的异常都在这里截住，出错只丢掉这一环这一帧的结果，后面照常更新。每处错误按位置、异常类型和堆栈第一行去重，日志里只记一次完整堆栈，前缀 `[外交大修]`。

- **单位**：校验任务、决策、执行 AI 这三步（`BatchActors.b4_checkTaskVerifier`、`b6_0_updateDecision`、`b6_updateAI`，循环由 `Guard.cs` 接管）逐个单位兜住异常。出错的单位停下手头的事（`cancelAllBeh`）；同一个单位再出错，先离开军队再停下。任务和军队对不上是这类错误最常见的来源。
- **批处理任务**：`Batch.runUpdater` 挂 Finalizer，单位、建筑等任何批处理任务出错，只丢掉这个任务这一帧的结果。`Batch<T>` 对引用类型共用一份代码，补丁挂在 `Batch<Actor>` 上，所有批次都生效。
- **城市、战争**：原版逐个对象调 `City.update`、`War.update`，兜在对象上，一座城出错不影响其他城。
- **子系统**：`MapBox` 的城市、单位、建筑、世界行为、地图图层更新，军队、国家、外交、亚种、密谋、家族、联盟、战争、状态效果各自的 `update`，都挂 Finalizer。
- **模拟和画面**：整个模拟步骤（`updateSimulation`）再兜一层，模拟出错不影响之后的玩家操作（`PlayerControl.updateControls`）、名牌（`NameplateManager.update`）和渲染（`renderStuff`），这三处也各自兜住。
- **并行任务**（属性重算）不经过 `runUpdater`，并行阶段里模组自己的补丁（单位伤害倍数、属性池）各自兜住异常。
- **弹道**：原版逐支登记「这个国家还有箭在飞」再更新弹道。一支箭出错，它后面的箭不再登记也不再更新；出错的箭不会被移除，于是每帧如此。`ProjectileManager.updateProjectiles` 由模组照原版逐支执行，每支箭各自兜住异常，出错的箭直接移除。

开发命令 `safety throw on` 让一座城的原版更新每帧抛异常，检查这一层：游戏照常运行，日志只记一次。

### 弹道的国家

弹道发射时记下射手的国家，飞行中每帧按它找附近的敌人。这个国家已经被移除时，找敌人读已清空的 `asset`，抛空引用，就是上面那种每帧报错、画面停住的情况。弹道找敌人之前检查这个国家，已移除就改用射手现在的国家；射手的国家也没了，就当没射中，箭照常落地。原版本该等一个国家的箭都落地再移除它，还有箭在飞就被移除时，日志里记一条从哪里移除的（每条路径一次），用来查清是哪条路径绕过了这个检查。开发命令 `bench arrow` 可以复现。

### 根源

兜底只防止出错扩散，出错的那段逻辑仍然没执行，根源要修掉。最常见的根源是拿着已经灭亡的对象：原版销毁国家时会清空它的 `asset` 和 `data`，之后对它判断敌友、读政策都会空引用。军队的城市没了时，原版 `Army.getKingdom` 返回军队记着的旧国家，可能就是这样一个已灭亡的国家。模组里取军队的国家一律用 `Orders.KingdomOf`，已灭亡的返回 null。

`tools/perf-check.sh` 跑完会数运行期间日志里的异常，应该是 0。不抛异常、只让对象之间的关系出错的问题（附庸的宗主已移除、单位属于已移除的国家），用开发命令 `check` 巡检，`tools/soak.sh` 长跑时每段查一次。
