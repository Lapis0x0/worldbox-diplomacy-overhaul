## 系统之间的关系

- **王朝周期是中枢。** 周期阶段影响附庸好感、城市忠诚、附庸会不会密谋独立、大国会不会分封城市、弱国会不会称臣，也决定共和国能不能称帝、将领能不能夺权。
- **战争靠谈判结束。** 打到差不多时交战双方和谈，按战果赔款、让出附庸或称臣，见[和谈](peace.md)。
- **附庸是外交的基本单位。** 投降、分封、称臣都产生附庸；附庸和宗主组成一个集团，战争同进同退；周期衰落时附庸离心，大叛乱时附庸纷纷独立。
- **政体跟着国家的经历变。** 新国家按文化掷出政体，之后由王室绝嗣、称帝、夺权和议会改变；成为附庸、获得独立都会改变称号。
- **钱有去处。** 城主上缴的钱进国库，城市用自己仓库的金子养兵，多余的上缴；国库养禁军、置办军械、出钱营建，国王发起密谋、战败赔款都动国库；市场让城市更富，见[国库、军饷与营建](economy.md)。
- **国策由氏族决定。** 各氏族按占的城分得议席，按立场表决税收、分封、政体、海军、战和、对待附庸和宗主的政策；扩张后地方氏族坐大，能和王室分庭抗礼。

## 本地开发

- 把仓库放进（或软链接到）`worldbox/Mods/DiplomacyOverhaul`，NML 启动时会编译 `Code/` 下的源码；`bin/`、`obj/` 和以 `.` 开头的文件不会被编译或上传
- 本地编译检查：`dotnet build`（需要 .NET SDK，引用游戏目录里的程序集）
- 热重载：游戏开着时运行 `tools/hot-reload.sh`，改动会在一两秒内生效，不用重启游戏
  - 改 `Core/Main.cs`、`Core/DevReload.cs`、`mod.json`、`default_config.json` 仍需重启
  - `Core.Start` 必须能重复执行：资源用 `Core.Upsert` 注册，Tab 按钮会被清掉重建
- 发版：改 `mod.json` 的版本号，在 `CHANGELOG.md` 写好这个版本的中英文说明并提交，然后运行 `tools/release.sh`。脚本检查工作区、版本号、语言文件和编译后打 tag 推送，GitHub Actions 自动建 Release 并附上发布包（`tools/package.sh` 也可以单独打包）
- 上传创意工坊：运行 `tools/workshop.sh`，用 SteamCMD 上传发布包里的文件和这个版本的更新说明，标题和简介不动。需要 `brew install --cask steamcmd`，把 Steam 账号名写进 `bin/steam_user`，第一次先在终端里 `steamcmd +login <账号名> +quit` 登录。也可以在 NML 模组列表里连点封面 8 次后等 3 秒打开上传窗口，但更新说明框有长度限制，长的说明会被截断

## 代码结构

| 目录 | 内容 |
|---|---|
| `Code/Core/` | 启动和热重载、设置、年月节奏（`Clock.cs`）、多个系统共用的原版挂点（`Hooks.cs`）、密谋动机、世界日志、异常隔离（`Isolation.cs`）、原版毛病的兜底（`Compat.cs`） |
| `Code/Diplomacy/` | 附庸、阵营、封建、整合度、独立、和谈、联盟地图 |
| `Code/Government/` | 政体、王朝周期、议会与政策、氏族与选官 |
| `Code/Economy/` | 国库与军饷、建筑增幅、营建 |
| `Code/Military/` | 军队命令、禁军和国家指挥、攻城、框选下令 |
| `Code/UI/` | 窗口和王国的显示 |
| `Code/Powers/` | 神力和 Tab |
| `Code/Perf/` | 性能优化和开发命令 |

每个系统一个静态类，自己的数据键、补丁、好感和忠诚项都放在自己的文件里，在 `Init` 里注册。按年或按月跑的逻辑加进 `Clock.cs`；一个原版方法被几个系统同时用到时，只在 `Hooks.cs` 挂一个补丁，在里面按顺序调用各系统（`Perf/` 自成一体，不在此列）。

## 时间

模组里的"年"是原版的游戏年（60 个世界时间单位，原版一个月是 5）。

| 频率 | 做什么 |
|---|---|
| 每年 | 政体事件（任期、夺权、称帝）→ 政体称号更新 → 王朝周期推进 → 整合度变动 → 强制同化 → 城市发地方兵军饷、多余的金子上缴国库、国库发禁军军饷 → 军械 → 首都雕像的声望 → 营建 → 到期的国家开议会 |
| 原版的密谋节奏（每位国王约 1–1.5 年一次） | 国王按动机考虑独立、威逼称臣、中兴、分封宗室、收归直辖、和谈密谋 |
| 每场战争每年 | 没人在谈时，双方国王按动机考虑发起和谈 |
| 大约每月 | 把所有附庸的战争状态和宗主同步一次 → 各城禁军人数向兵制名额调整 → 国家给禁军编队派任务 → 地方军安排驻守和出击 |
| 原版的决策节奏 | 立新君主、城市挑进攻目标、军队行动，模组在这些原版流程里插入自己的逻辑 |

## 数据保存

模组的状态都写在原版对象的自定义数据里（`kingdom.data`、`city.data`、`war.data`），随原版存档保存，键名都以 `vd_` 开头。装模组之前的存档可以直接用：缺少的数据在第一次判定时补上。

只有一样东西不进存档：玩家下的**进攻命令**。读档或热重载后，城市回到原版 AI 挑目标。驻扎、扎营是存档的。

## 与其他模组

王国之间的好感逐项计算：某一项（原版的、本模组的或其他模组加的）出错时，这一项按 0 计，其余照常累加。每个出错的项只在日志里记一次，带上项的 id 和两个王国的名字。原版遇到这种情况会让整次计算作废并报错，每次算好感都会刷屏。

原版存档时会按 id 重新找一遍外交关系里的两个王国，找不到就把引用留空，关系本身却还在，之后这两国每次算好感都会报错。取外交关系时如果发现引用为空，就用这次传进来的两个王国补上。

## 异常隔离

原版每帧的更新没有异常保护，一处抛异常，这一帧排在后面的更新全被跳过，条件不变就每帧如此。模组分两层防护：

- **模组这一侧**：每个前缀、后缀补丁先问 `Safety.On(系统)`，逻辑包在 `try` 里，出错交给 `Safety.Fail` 并照原版；同一个系统频繁出错就本局停用（熔断）。不需要兜底的补丁标 `[SafeBy("理由")]`，开发时启动会审计
- **原版这一侧**：逐个对象、逐个子系统兜住异常（`Isolation.cs`），出错只丢掉这一环这一帧的结果；持续出错时提示玩家，并标出出错的模组

写法、例外和每一环的挂点见[异常隔离](isolation.md)。
